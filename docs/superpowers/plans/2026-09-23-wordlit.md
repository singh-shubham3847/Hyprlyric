# Wordlit Implementation Plan

> **Historical document.** The app was codenamed **Wordlit** while it was designed and built, and shipped as **Hyprlyric**. Names, paths and `WORDLIT_*` variables below use the old codename.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Windows tray app. It shows the lyrics of the song playing in Spotify or Apple Music and lights each word as it is sung, in four animated styles (Ship, Fisheye, Fisheye Visual, Visual). The lyrics appear on a full-screen lock-style screen or on an always-on overlay.

**Architecture:**
- **Electron main (TypeScript):**
  - reads Windows media sessions through a Windows PowerShell 5.1 WinRT bridge (`smtc-bridge.ps1`)
  - fetches line-synced lyrics from LRCLIB (local `.lrc` and a disk cache first) and estimates per-word timing
  - builds a palette from album art
  - drives windows, tray, idle, hotkey and power
- **Sandboxed renderer:** draws the styles with CSS 3D and a WebGL lens shader, using an extrapolated song clock.

**Tech Stack:** Electron 44.4.4, electron-vite 5.0.0, Vite ^7, TypeScript 6.0.3, Vitest 5.0.1, yaml 2.9.1, @fontsource-variable/inter 5.3.0, @iconify-json/fluent 1.2.58, @electron/packager 20.3.0, @types/node ^24.9.

**Spec:** `docs/superpowers/specs/2026-09-23-wordlit-design.md`

## Global Constraints

- Platform: Windows 10 1809+ / Windows 11 x64. Target PC: Win 11 26200, one 1536×864 DIP display, Node 26.3.1, npm 11.16, Windows PowerShell 5.1 present, no .NET SDK, no Rust.
- Pin Vite to `^7` (electron-vite 5 peer range is `^5 || ^6 || ^7`).
- No `"type": "module"` in package.json. Main and preload build to CommonJS, which a sandboxed preload requires.
- All libraries go in `devDependencies` and are bundled by electron-vite. `dependencies` stays empty, so the packaged app ships no `node_modules`.
- Renderer security: `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, a CSP meta tag, and `window.open` and navigation denied.
- **No real song lyrics anywhere in the repo.** Fixtures, the demo song and E2E lyrics are original text written for this project. Live LRCLIB checks assert on metadata only and never print lyric text.
- Default colours: lyric `#DC372A`, highlight `#CA415E`, highlight text `#FFF1F3`, secondary `#E7B9C2`.
- Times inside lyrics and clock code are integer **milliseconds of song time**. Wall-clock anchors are epoch ms.
- LRCLIB: `User-Agent: Wordlit/0.1.0 (Windows lyrics overlay)`, an 8 s timeout, 3 retries on 429/5xx/network errors, and a 3-day TTL on not-found results.
- Hotkey `CommandOrControl+Alt+L`. Idle default 2 min. Grace period after opening the lock screen: 1200 ms.
- No git commits unless the user asks (harness rule). Checkpoints are `npm run typecheck && npm test`.
- Shell: PowerShell is primary. `npm`/`npx` work from PowerShell.

### Execution notes (what changed during implementation)

- **Live LRCLIB check.** This became an opt-in Vitest suite (`tests-live/`, `npm run check:lrclib`) instead of `scripts/check-lrclib.mjs`. That lets it reuse the TypeScript modules directly. It still asserts and prints metadata only.
- **Visual style.** It shows one word at a time with its icon, which matches Verci's demo frames. It does not lay out the whole line.
- **Performance.**
  - *Finding:* profiling showed the GPU process at ~58 % of one core from rendering a full-screen window at a constant 60 fps.
  - *Fix:* styles now report whether a transition is running. The stage renders at full rate only then (60 fps on the lock screen, 30 over the desktop) and at 24 / 15 fps for the ambient drift. The CSS `mask-image` clock fade was replaced by a per-word fade (Ship) and a shader fade (Fisheye). Inline styles are only written when they change.
  - *Result:* ~22 % (lock screen) and ~14 % (overlay) of one core for the GPU process.
- **Tray label.** The lock trigger in the tray is labelled "Lock with Lyrics", because it locks Windows on return, like the hotkey.
- **First-run notice.** A `welcomed` setting was added. Windows 11 hides new tray icons, so the first run shows a notification explaining Ctrl+Alt+L.
- **Debug flags for E2E.** `--open-lock-after`, `--return-after` (DOM input: Chromium only routes injected OS input to focused windows), `--capture-after/--capture-file`, `--capture-colors` and `--quit-after`, plus `WORDLIT_NO_LOCK=1`.
- **Packaging.** `node_modules` is ignored entirely; everything is bundled, and the asar holds only `out/` and `package.json`.
